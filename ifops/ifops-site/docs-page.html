Getting Started Last updated: 2024

IFOps (Infrastructure Operations) is a powerful command-line tool for managing AWS infrastructure. It provides both imperative commands for direct resource management and declarative infrastructure as code using YAML configuration files similar to Terraform.

Introduction

IFOps addresses several key challenges in AWS infrastructure management:

  • Simplified CLI: Intuitive, memorable commands instead of complex AWS CLI syntax
  • Infrastructure as Code: Terraform-like declarative configuration through YAML files
  • Multi-Service Management: Unified interface for EC2, S3, ECR, ECS, App Runner, Amplify, SSL, and CI/CD
  • Multi-Account Support: Built-in profile management for multiple AWS accounts
  • State Management: Automatic tracking of deployed resources
Supported AWS Services:
EC2 Create, manage, start, stop, terminate instances
S3 Buckets, uploads, sync, static sites, CORS
ECR Docker image repositories
ECS Container orchestration clusters
App Runner Serverless container deployments
Amplify Frontend hosting and CI/CD
ACM SSL/TLS certificates
CI/CD Deployment pipelines

Installation

IFOps requires Python 3.9 or higher. Choose your preferred installation method:

Automated Installation
# Clone repository
git clone https://github.com/yourusername/ifops.git
cd ifops

# Run installation script
./install.sh

# Activate virtual environment
source venv/bin/activate
Manual Installation
# Create virtual environment
python3 -m venv venv
source venv/bin/activate

# Install package
pip install -e .

# Or with development dependencies
pip install -e ".[dev]"
Dependencies
# Core dependencies
typer[all] >= 0.9.0
rich >= 13.0.0
boto3 >= 1.28.0
botocore >= 1.31.0
pyyaml >= 6.0

Note

Make sure you have AWS credentials configured before using IFOps. You can configure them using ifops configure --setup or use existing AWS credentials from ~/.aws/credentials.

Quick Start

Get up and running with IFOps in minutes:

1. Configure AWS Credentials
# Interactive setup wizard
ifops configure --setup

# Verify credentials
ifops configure --verify
2. Create Your First S3 Bucket
# Create a bucket with versioning enabled
ifops s3 create my-first-bucket --versioning --region us-east-1

# List all buckets
ifops s3 list
3. Launch an EC2 Instance
# Create an EC2 instance
ifops ec2 create web-server \
  --ami ami-0c7217cdde317cfec \
  --type t3.micro \
  --key my-key-pair

# Check instance status
ifops ec2 list --state running
4. Or Use Declarative Mode
# Create a project
ifops project create my-app --region us-east-1

# Edit infra.yaml, then plan and apply
ifops project plan my-app
ifops project apply my-app

CLI Structure

IFOps uses a hierarchical command structure:

ifops [GLOBAL_OPTIONS] COMMAND [SUBCOMMAND] [ARGUMENTS] [OPTIONS]
Global Options
Option Description
--verbose Enable verbose output
--debug Enable debug mode with full tracebacks
--profile <name> Use specific AWS profile
Example Usage
# Use production profile with verbose output
ifops --profile production --verbose ec2 list --region eu-west-1

# Check version
ifops version

EC2 Management

Manage Amazon EC2 instances with simple, intuitive commands. Create, list, start, stop, terminate, and modify instances with ease.

Create Instance

Create a new EC2 instance with the ifops ec2 create command:

ifops ec2 create <name> --ami <ami-id> [OPTIONS]
Options
Option Description Default
--ami AMI ID (required) -
--type Instance type t3.micro
--key SSH key pair name -
--sg Security group IDs (comma-separated) -
--subnet Subnet ID -
--user-data Path to user data script -
--volume-size Root volume size in GB 8
--region AWS region default
Example
# Create a web server instance
ifops ec2 create web-server \
  --ami ami-0c7217cdde317cfec \
  --type t3.small \
  --key production-key \
  --sg sg-12345678,sg-87654321 \
  --volume-size 20 \
  --region us-east-1

List & Status

List Instances
# List all instances
ifops ec2 list

# Filter by state
ifops ec2 list --state running
ifops ec2 list --state stopped

# Specify region
ifops ec2 list --region eu-west-1
Get Instance Status
# Get detailed status of an instance
ifops ec2 status i-1234567890abcdef0

The status command shows detailed information including:

  • Instance ID and Name
  • State (running, stopped, etc.)
  • Instance type
  • Public and private IP addresses
  • Launch time
  • Security groups

Start, Stop & Terminate

Start Instances
# Start one or more instances
ifops ec2 start i-1234567890abcdef0
ifops ec2 start i-1234567890abcdef0,i-0987654321fedcba0
Stop Instances
# Stop an instance (without terminating)
ifops ec2 stop i-1234567890abcdef0
Terminate Instances
# Terminate an instance (permanent)
ifops ec2 terminate i-1234567890abcdef0

# Skip confirmation prompt
ifops ec2 terminate i-1234567890abcdef0 --force

Warning

Terminating an instance is permanent and cannot be undone. All data on instance store volumes will be lost. Use stop if you want to preserve the instance.

Modify Instance

Modify instance attributes (instance must be stopped first):

# Stop the instance first
ifops ec2 stop i-1234567890abcdef0

# Modify instance type
ifops ec2 modify i-1234567890abcdef0 --type t3.medium

# Start the instance again
ifops ec2 start i-1234567890abcdef0

S3 Storage

Manage Amazon S3 buckets for object storage. Create buckets, upload files, configure static websites, and set up CORS policies.

Bucket Operations

Create Bucket
# Create a basic bucket
ifops s3 create my-bucket

# Create with versioning enabled
ifops s3 create my-bucket --versioning

# Create in specific region
ifops s3 create my-bucket --region eu-west-1

# Create with public access (use carefully!)
ifops s3 create my-bucket --public
List Buckets
# List all buckets in the account
ifops s3 list
Delete Bucket
# Delete an empty bucket
ifops s3 delete my-bucket

# Force delete (removes all objects first)
ifops s3 delete my-bucket --force

Upload & Sync

Upload Files
# Upload a single file
ifops s3 upload my-bucket --source ./file.txt

# Upload directory recursively
ifops s3 upload my-bucket --source ./dist --recursive

# Upload with prefix (folder in S3)
ifops s3 upload my-bucket --source ./dist --recursive --prefix v1.0.0
Sync Directory
# Sync local directory to S3
ifops s3 sync my-bucket --source ./dist

# Sync with delete (removes files in S3 not in source)
ifops s3 sync my-bucket --source ./dist --delete

# Sync with prefix
ifops s3 sync my-bucket --source ./dist --prefix assets/

Tip

Use sync for deployments as it only uploads changed files, making it faster and more efficient than upload.

Static Site & CORS

Configure Static Website
# Enable static website hosting
ifops s3 static-site my-bucket

# Custom index and error documents
ifops s3 static-site my-bucket --index index.html --error 404.html
Configure CORS
# Allow all origins
ifops s3 cors my-bucket

# Specify allowed origins
ifops s3 cors my-bucket --origins "https://example.com,https://app.example.com"

Container Services

Manage Docker containers with ECR (Elastic Container Registry) for image storage and ECS (Elastic Container Service) for orchestration.

ECR Repository

Create Repository
# Create a repository with scanning enabled
ifops ecr create my-app-repo --scan

# Create with tag immutability
ifops ecr create my-app-repo --scan --immutable

# Specify encryption type
ifops ecr create my-app-repo --encryption KMS
List Repositories
ifops ecr list
Delete Repository
# Delete empty repository
ifops ecr delete my-app-repo

# Force delete (removes all images)
ifops ecr delete my-app-repo --force
Docker Login
# Print docker login command
ifops ecr login --region us-east-1

# Execute login directly
ifops ecr login --region us-east-1 --execute

ECR Images

List Images
ifops ecr images my-app-repo
Delete Image
# Delete by tag
ifops ecr delete-image my-app-repo --tag v1.0.0

# Delete by digest
ifops ecr delete-image my-app-repo --digest sha256:abc123...

ECS Clusters

Create Cluster
# Create with Fargate capacity providers
ifops ecs create-cluster production-cluster

# Specify capacity providers
ifops ecs create-cluster production-cluster \
  --capacity-providers FARGATE,FARGATE_SPOT
List Clusters
ifops ecs list-clusters
Delete Cluster
ifops ecs delete-cluster production-cluster

Deployment Services

Deploy applications to AWS using App Runner for containerized apps and Amplify for frontend applications.

App Runner

Create Service
ifops apprunner create my-service \
  --image 123456789.dkr.ecr.us-east-1.amazonaws.com/my-app:latest \
  --port 8080 \
  --cpu 1024 \
  --memory 2048 \
  --role arn:aws:iam::123456789:role/AppRunnerRole
Options
Option Description Default
--image ECR image URI (required) -
--port Container port 8080
--cpu CPU units (256, 512, 1024, 2048, 4096) 1024
--memory Memory in MB 2048
--role IAM role ARN for ECR access (required) -
--auto-deploy Enable auto deployments false
Other Commands
# List services
ifops apprunner list

# Get status
ifops apprunner status <service-arn>

# Trigger deployment
ifops apprunner deploy <service-arn>

# Delete service
ifops apprunner delete <service-arn>

Amplify

Create Application
ifops amplify create my-frontend \
  --repo https://github.com/user/repo \
  --branch main \
  --token ghp_xxxxxxxxxxxx
Other Commands
# List applications
ifops amplify list

# Get deployment status
ifops amplify status <app-id>

# Trigger deployment
ifops amplify deploy <app-id>

# Configure custom domain
ifops amplify domain <app-id> --domain example.com

# Delete application
ifops amplify delete <app-id>

SSL & CI/CD

Manage SSL certificates with AWS Certificate Manager (ACM) and automate deployments with CI/CD pipelines.

SSL Certificates

Request Certificate
# Request SSL certificate with DNS validation
ifops ssl request example.com

# Include alternative names
ifops ssl request example.com \
  --alt-names "www.example.com,api.example.com"

# Use email validation instead
ifops ssl request example.com --validation EMAIL
List Certificates
# List all certificates
ifops ssl list

# Filter by status
ifops ssl list --status ISSUED
ifops ssl list --status PENDING_VALIDATION
Other Commands
# Get certificate status
ifops ssl status <certificate-arn>

# Validate DNS records
ifops ssl validate-dns <certificate-arn>

# Renew certificate
ifops ssl renew <certificate-arn>

# Delete certificate
ifops ssl delete <certificate-arn>

CI/CD Pipelines

Build and Push to ECR
# Build and push Docker image
ifops cicd ecr-push my-app-repo --tag v1.0.0

# Custom Dockerfile
ifops cicd ecr-push my-app-repo \
  --tag v1.0.0 \
  --dockerfile ./docker/Dockerfile.prod \
  --context .
Deploy to Services
# Deploy to ECS
ifops cicd deploy-ecs my-cluster \
  --service my-service \
  --force

# Deploy to App Runner
ifops cicd deploy-apprunner <service-arn>

# Deploy to Amplify
ifops cicd deploy-amplify <app-id>

# Deploy to S3
ifops cicd deploy-s3 my-bucket --source ./dist
Pipeline Management
# List pipelines
ifops cicd list-pipelines

# Get pipeline status
ifops cicd status <pipeline-name>

# Trigger pipeline manually
ifops cicd trigger <pipeline-name>

Declarative Mode

Define your infrastructure in YAML files and manage it like Terraform. Plan changes, apply configurations, and track state automatically.

Project Commands

Create Project
# Create a new project
ifops project create my-web-app --region us-east-1

# With description
ifops project create my-web-app \
  --region eu-west-3 \
  --description "Production web application"

This creates an infra.yaml file in the current directory and state in ~/.ifops/projects/my-web-app/.

List Projects
ifops project list
Show Project
ifops project show my-web-app
Plan Changes
# See what changes will be made
ifops project plan my-web-app

Shows resources to create (+), destroy (-), and unchanged (=).

Apply Changes
# Apply with confirmation
ifops project apply my-web-app

# Skip confirmation
ifops project apply my-web-app --auto-approve
Destroy Resources
# Destroy all resources
ifops project destroy my-web-app

# Skip confirmation
ifops project destroy my-web-app --auto-approve
Delete Project
# Delete project config and state
ifops project delete my-web-app

# Force delete even if resources exist
ifops project delete my-web-app --force
Show Available Resources
ifops project resources

infra.yaml Format

The infra.yaml file defines your infrastructure:

name: my-web-app
description: Production web application
region: us-east-1

resources:
  - type: ecr
    name: my-app-repo
    scan_on_push: true

  - type: s3
    name: my-assets-bucket
    versioning: true
    static_site: true

  - type: ec2
    name: web-server
    ami: ami-0c7217cdde317cfec
    instance_type: t3.small
    key_name: my-key
    volume_size: 20

  - type: ecs-cluster
    name: app-cluster
    capacity_providers:
      - FARGATE
      - FARGATE_SPOT

Resource Types

ECR Repository
- type: ecr
  name: my-repo
  scan_on_push: true      # Enable vulnerability scanning
  immutable: false        # Tag immutability
  encryption: AES256      # Encryption type (AES256 or KMS)
S3 Bucket
- type: s3
  name: my-bucket
  versioning: true        # Enable versioning
  static_site: true       # Static website hosting
  public: false           # Public access
  cors_origins:           # CORS origins
    - "*"
EC2 Instance
- type: ec2
  name: my-server
  ami: ami-0123456789abcdef0
  instance_type: t3.micro
  key_name: my-key
  security_groups:
    - sg-12345678
  subnet_id: subnet-12345678
  volume_size: 20
  user_data: /path/to/script.sh
ECS Cluster
- type: ecs-cluster
  name: my-cluster
  capacity_providers:
    - FARGATE
    - FARGATE_SPOT
  container_insights: true

Configuration

Configure IFOps credentials, manage multiple AWS profiles, and customize settings for your workflow.

Credential Setup

Interactive Setup
# Start interactive credential setup
ifops configure --setup

The setup wizard will prompt for:

  • AWS Access Key ID
  • AWS Secret Access Key
  • Default region
  • Profile name
Verify Credentials
# Verify default profile
ifops configure --verify

# Verify specific profile
ifops configure --verify --profile production
Show Configuration
# Show all configuration
ifops configure --show

# Show specific profile
ifops configure --profile my-profile

Multiple Profiles

IFOps supports multiple AWS profiles for managing different accounts or environments:

Create Multiple Profiles
# Run setup multiple times with different profile names
ifops configure --setup  # Creates 'default'
ifops configure --setup  # Creates 'production'
ifops configure --setup  # Creates 'staging'
Use Profiles
# Use with any command
ifops --profile production ec2 list
ifops --profile staging s3 list
ifops --profile default ecr list

Credential Lookup Order

IFOps looks for credentials in this order:

  1. --profile CLI argument
  2. AWS_PROFILE environment variable
  3. ~/.ifops/credentials file
  4. ~/.aws/credentials file (standard AWS)

FAQs

Frequently asked questions about IFOps usage, troubleshooting, and best practices.

General Questions

What is the difference between imperative and declarative mode?

Imperative mode uses direct commands like ifops ec2 create for immediate operations. Declarative mode uses infra.yaml files to define desired state, then applies changes with ifops project apply. Declarative mode is better for reproducible infrastructure and version control.

Can I use IFOps with existing AWS resources?

Yes! Imperative commands work with any AWS resources. For declarative mode, you would need to define matching resources in your infra.yaml - IFOps will detect existing resources during plan.

Does IFOps support all AWS services?

Currently IFOps supports EC2, S3, ECR, ECS, App Runner, Amplify, ACM (SSL), and CI/CD pipelines. More services will be added in future versions.

How is IFOps different from Terraform?

IFOps is simpler and focused on common AWS use cases. It combines imperative CLI commands with declarative config. Terraform is more comprehensive but has a steeper learning curve. IFOps is great for quick AWS deployments and smaller projects.

Troubleshooting

I get "credentials not found" error

Run ifops configure --setup to configure your AWS credentials, or ensure your ~/.aws/credentials file is properly configured.

Commands are using wrong region

Specify the region explicitly with --region flag, or set it in your profile configuration. Check current settings with ifops configure --show.

EC2 modify command fails

The instance must be stopped before modifying attributes like instance type. Use ifops ec2 stop first.

S3 bucket creation fails with "bucket already exists"

S3 bucket names must be globally unique across all AWS accounts. Try a more specific name like mycompany-myproject-bucket.

Project apply shows no changes but resources don't exist

Check if the state file is out of sync. You can delete the state at ~/.ifops/projects/[name]/state.json and run apply again.

Best Practices

How should I organize my infrastructure?
  • Use separate profiles for different environments (dev, staging, production)
  • Use declarative mode for production infrastructure
  • Version control your infra.yaml files
  • Use meaningful names for resources
What's the recommended workflow?
  1. Create a project: ifops project create my-app
  2. Define resources in infra.yaml
  3. Review changes: ifops project plan my-app
  4. Apply changes: ifops project apply my-app
  5. Commit infra.yaml to version control
How do I handle secrets?

Never commit credentials to version control. Use AWS Secrets Manager or Parameter Store for application secrets. IFOps credentials should stay in ~/.ifops/credentials which is not version controlled.

Should I use --force flags?

Use --force flags with caution, especially for delete operations. They skip confirmation prompts and can lead to accidental data loss. Only use in automation scripts where you're certain of the operation.
